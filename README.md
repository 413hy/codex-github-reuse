# GitHub 复用优先开发 · Codex Skill

> 先理解项目，再研究合适的 GitHub 方案；经过判断和适配，直接交付完整可运行 demo。

这是一个供 **Codex 跨项目使用的开发技能配置包**，由 Skill、常驻入口规则和本地安装器组成。
它让 AI 在开发前读懂需求与已有代码，找到值得参考的页面设计、交互逻辑、功能实现、架构或 prompt，
再结合当前项目完成开发，减少重复造轮子和生硬拼接。

| 项目概况 | 内容 |
| --- | --- |
| 技能名称 | `github-reuse-first` |
| 显式调用 | 在 Codex 对话中使用 `$github-reuse-first` |
| 主要用途 | 新项目、重要功能开发、UI/UX 改版、技术选型、prompt 与 agent 工作流设计 |
| 核心组成 | Markdown 技能与规则、YAML 入口配置、Python 安装器 |
| 默认交付 | 覆盖已明确需求的完整 demo、运行方式、适配说明与实际自检结果 |

## 给第一次读取本仓库的 AI

本仓库维护的是 **Codex 的开发方法与配置**；业务 demo 在用户指定的目标项目中实现。

- **用户要了解这个仓库：** 先解释项目用途、安装方式和使用方法。
- **用户要安装：** 读取 [安装说明](INSTALL.zh-CN.md)，在实际运行 Codex 的机器和用户环境下完成安装。
- **用户要用它开发项目：** 进入目标项目，调用并遵循 [主技能](skills/github-reuse-first/SKILL.md)。
- **用户要修改这套 Skill：** 根据需求维护对应规则、参考说明或安装器，并检查相关文档是否一致。

## 快速开始

### 最省事：让 Codex 安装

将本仓库下载或克隆到本地，用 Codex 打开包含 `install.py` 的目录，把下面这段发送给它：

```text
请阅读当前目录的 README.md 和 INSTALL.zh-CN.md，
将 github-reuse-first 安装为当前用户的全局 Codex Skill。

优先使用本项目的 install.py；
保留已有规则，发生改动时自动备份并更新。
安装完成后报告实际写入路径，并检查技能和常驻入口是否已正确配置。
如果没有可用的 Python，按安装说明中的手动方式完成。
```

安装器要求 **Python 3.9 或更高版本**，只使用标准库。
安装完成后，重新开启 Codex 会话，再在要开发的项目中调用技能。

### 自己执行安装命令

在包含 `install.py` 的目录中，按当前系统执行对应命令。

**Windows：**

```powershell
py -3 install.py --global
```

**Linux / macOS / WSL：**

```bash
python3 install.py --global
```

全局安装适用于当前用户的多个项目。安装器将技能放入 `~/.agents/skills/github-reuse-first/`，
并将入口规则合并到有效的全局指令文件：默认是 `~/.codex/AGENTS.md`；
设置了 `CODEX_HOME` 时使用该目录，存在有效 `AGENTS.override.md` 时合并到覆盖文件。
具体路径选择与保留已有配置的方式见 [安装说明](INSTALL.zh-CN.md)。

只在一个项目中使用时，在本仓库目录运行以下命令，把示例路径替换为**已经存在的目标项目目录**：

```bash
python3 install.py --project "/absolute/path/to/project"
```

Windows 将 `python3` 换成 `py -3`。项目安装会写入目标项目的 `.agents/skills/` 和有效的项目指令文件。

**上传到 GitHub 用于保存和分发这些文件；实际使用仍需要在运行 Codex 的环境中安装。**
Windows 原生、WSL 和 VPS 各自使用所在环境的用户配置。

## 安装后怎么用

在新的 Codex 会话中打开要开发的项目，发送下面的示例，并填入实际需求：

```text
使用 $github-reuse-first 开发这个项目。

我的需求：
【在这里写你要实现的功能、页面、使用流程和偏好】

先把我的需求全部理解好，有任何需求疑问立即停下相关工作并向我提问。
明确后先阅读已有项目，再去 GitHub 查找适合参考或复用的方案。
读懂参考方案后，判断哪些有用，并按当前项目的技术栈、接口和设计进行适配。
直接完成覆盖已明确需求的完整可运行 demo，由你自行检查和修复。
成品默认直接可用，不额外添加登录、激活、审批、解锁或使用次数等门槛。
完成后说明如何运行、借鉴了什么、怎样适配，以及实际验证结果。
之后再根据我的反馈继续优化。
```

入口规则已加载时，适用任务会被要求使用这套工作流；首次使用明确点名技能更容易检查是否生效。
如未发现技能，使用 `/skills` 查看，或按 [安装说明](INSTALL.zh-CN.md) 检查发现路径与指令来源。

常见用法包括：为已有后台增加表格交互、统一页面设计、开发 Bot 功能、完善 CLI 工具，
以及改进 prompt 的输入输出约定。更多可直接使用的请求见 [使用示例](EXAMPLES.zh-CN.md)。

## AI 应如何完成开发

1. **理解全部需求。** 阅读相关项目说明、已有实现、依赖和设计约定。对需求含义有疑问就及时问；需求明确后的常规实现选择由 AI 自行处理。
2. **按实际缺口研究。** 先利用项目已有能力，再搜索与当前任务相关的 GitHub 仓库，并阅读具体代码、文档、示例和适用许可。
3. **说明选择与适配。** 判断参考方案解决什么问题、哪些部分适用、需要如何改动，保持项目接口和视觉一致。
4. **完成完整 demo。** 首轮覆盖全部已明确需求，准备入口、关键交互、示例数据与运行说明。
5. **自行检查和修复。** 根据改动执行必要检查，报告真实结果；用户反馈用于后续迭代，不作为允许继续开发的前置审批。
6. **保留可追溯记录。** 记录来源、采用或放弃理由、本地落点和验证状态；继续同一任务时先沿用已有研究。

小范围文案修改、纯解释和根因明确的局部修复，不自动启动完整 GitHub 调研；
用户当次明确要求调研、只读分析或逐步指导时，按对应范围执行。
完整流程以 [主技能](skills/github-reuse-first/SKILL.md) 为准。

## 核心原则：理解后适配

**本 Skill 的每个文件都围绕实际需求组织和编写。**
参考仓库提供设计思路，采用哪些内容、怎样改写、如何组织文件，都由本项目的目标决定。
本包没有捆绑上游项目源码、完整第三方 Skill 或整套开发流程。

这套原则也适用于未来的开发任务：

- 每个采用项都要能解释：解决哪个需求、借鉴哪一部分、怎样接入当前项目。
- 合理使用成熟依赖、局部移植代码、借鉴设计或逻辑、改写 prompt；按兼容性、使用条件和整合成本选择方式。
- 页面与交互遵循统一设计，不把多个模板直接堆在一起。
- Prompt 和 Skill 按实际角色、工具、输入输出及目标行为重新组织。
- 不为使用某个仓库擅自更换整个技术栈，也不把固定“热门仓库清单”设为所有项目的必选项。
- 每个文件都应有明确用途；参考项目中的无关文件、专属工具假设和冲突规则不带入当前项目。

本包的研究来源、借鉴点与具体调整见 [来源与适配记录](SOURCES.md)。

## 完整 demo 与默认使用体验

完整 demo 应形成可以实际运行和体验的流程。
页面项目应包含主要页面与关键交互；CLI 应提供可运行入口和代表性输入；prompt 应能直接使用并附带样例。
交付时说明实际完成了哪些行为、运行方法、采用的方案和自检结果。

需求明确后，AI 直接推进研究、实现、自检、修复和交付，不另设方案审批、逐项授权或人工验收关卡。
成品默认不自行添加登录注册、激活码、验证码、审批、功能解锁、付费墙、次数或试用限制；
用户明确提出这些产品机制时，再按实际需求实现。必要的数据检查由程序自动完成。

外部服务暂不可用时，可提供明确标注的演示数据或可替换模拟实现，让本地流程可以体验。
真实服务的待接入部分必须说明，不能把模拟成功描述成真实集成已经完成。

## 维护这套 Skill

修改前先确认要调整的是技能工作方式、检索细则、质量要求，还是安装行为。
规则有变化时，同步检查主技能、常驻入口、调用示例和文档的一致性。
更新源文件后重新运行对应安装命令；安装器对相同内容不重复写入，对变化内容自动备份并更新。

修改安装器时，可在仓库根目录运行已有测试：

```bash
python3 -m unittest discover -s tests -v
```

Windows 将 `python3` 换成 `py -3`。历史测试结果和实际覆盖环境见 [验证记录](VALIDATION.md)。
仅修改文档时，核对内容与实现、链接和命令是否一致即可。

## 运行条件与官方依据

GitHub 搜索、文件操作、浏览器预览和代码执行来自 Codex 已有环境；
本包的安装器负责安装配置，联网检索由 Codex 在具体任务中完成。
技能提供明确工作方式，实际触发与执行还受模型、有效项目指令和可用工具影响；
运行环境与第三方服务原有的强制权限由对应平台管理。

格式和安装约定的依据：
[Codex Skills](https://learn.chatgpt.com/docs/build-skills)、
[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。
本包的具体行为以仓库中的技能正文、安装器与验证记录为准。
